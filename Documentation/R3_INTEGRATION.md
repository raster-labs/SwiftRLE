## Command line

`swiftrle-cli` provides encode/decode/inspect/validate/capabilities, help/version aliases and command-local help. Formats are explicit; `.rle` never selects a dialect. PackBits accepts raw bytes; decode/inspect/validate require `--decoded-bytes`, with optional consistent row geometry. DICOM frame raw endpoints require every external descriptor/layout field shown by help, including explicit planar configuration. These values are supplied by the application, not discovered in the 64-byte frame header. Inspect checks the header; validate decodes the complete frame. Unsupported modes, formats, backend requests and inapplicable flags fail before payload I/O when discoverable.

Binary stdout contains bytes only; encode/decode JSON reports and diagnostics use stderr. Inspect/capability reports use stdout. Verbosity is cumulative and bounded, with all CLI-08 spellings and ordering. Diagnostics omit paths, metadata, payload and addresses. File publication uses a sibling transaction with atomic no-replace hard-link publication by default; overwrite uses atomic rename. A competing creator cannot be overwritten by the default. The transaction contains final output only. Failure cleans it up. Stdout can contain a partial payload on failure and cannot be rolled back.

Reads/writes use nonblocking descriptors, 16 KiB chunks, poll backpressure and cancellation/deadline checks. One monotonic deadline covers the whole operation; each codec receives the time remaining immediately before its call. SIGINT/SIGTERM cancel, and broken pipes return 6. Input admission is finite and conservative: a 32 KiB I/O reserve plus per-buffer ceilings of `(maximumMemoryBytes - 32768) / 8` reserve input, parser payload, owner, compressed/raw output and temporary buffer growth separately; API aggregate admission uses half the process budget, workspace at most one quarter. Budgets below 65536 bytes fail. This deliberately rejects some operations that might fit a less conservative implementation. It never reads an unconstrained file or trusts declared sizes to enlarge limits.

A 29 October 2026 audit remediation aligns CLI backend routing and deadline conversion with the library contract: omitted `--backend` and explicit `--backend automatic` forward `ExecutionPolicy.automatic` (reaching R4's nonsingleton scalar address hoisting while still reporting `scalarCPU`), `--backend scalar` and `scalar-cpu` retain the explicit `scalarCPU` reference policy, `--backend preferred-accelerated` preserves fallback reporting, and `--backend required-accelerated` fails with exit `4`. Remaining operation deadline conversion samples the monotonic clock once at both initial and refreshed `ResourceLimits` construction, preserving cancellation priority (exit `130`) and rejecting nonpositive remaining time as deadline exceeded (exit `5`) before `ResourceLimits` validation. Production CLI routing lives in internal target `SwiftRLECLICore` (`CLIRunner.swift`, `Arguments.swift`, `IO.swift`, `NRRD.swift`) with `SwiftRLECLI` (`Entry/EntryPoint.swift`) providing the thin `@main` executable wrapper for `swiftrle-cli`, so `SwiftRLECLITests` verifies the actual options consumed by `Main.run` and deterministic clock boundaries in debug and release without linking executable entry symbols into test runners; no new CLI speedup measurement is claimed.

## Restricted NRRD profile

The parser was implemented after reviewing the [official NRRD specification](https://teem.sourceforge.net/nrrd/format.html), retrieved 24 October 2026, SHA-256 `43ca6102cc998e0191e225d7954278547d491e29b74a132b3118571d85a8b0d5`.

The qualified profile is attached ASCII header plus raw 2D unsigned full-precision UInt16 greyscale payload, fastest width axis and explicit endian. Header search itself is bounded: 16384 total bytes, 64 lines and 1024 bytes per line. LF/CRLF, case-insensitive field names/non-string values, trailing whitespace and space/tab sizes delimiters are supported. Required fields occur once; dimension precedes sizes. Exact checked dimensions and exact payload length are required. Unknown semantic fields, private keys, detached/URL/data-file references, skip offsets, compressed/ASCII encoding, colour/signed profiles and source-declared 12-in-16 output are refused. There is no external file/network access from metadata. Basic uint16 NRRD cannot preserve declared 12-bit precision.

## Real shared-storage package

`Integration/SharedStorage` is a separate package depending on local SwiftRLE and SwiftJLS revision `0791e54a5950bb8082af2218bce3800e03c777b9`. SwiftRLE core has no sibling dependency. No executable is invoked by the in-process transcoder. Its RLE/JPEG-LS adapters explicitly map local descriptors and lease tokens, retain one authoritative SwiftRLE owner, forward allocation identity and borrowed capacity, decode directly and seal, then encode from that same sealed owner. No decoded image serialization, intermediate file, pixel repack or handoff copy occurs.

The qualified directional profile is unsigned 12-in-16 or full16 greyscale, no ICC/ancillary metadata, packed samples with independently chosen padded rows and either byte order. JPEG-LS source must be lossless single-scan, without ancillary/mapping/restart semantics; near-lossless source history is refused rather than relabelled lossless. Explicit JPEG-LS marker preflight establishes this restriction because the peer public inspect result does not expose NEAR. The peer parser remains authoritative for complete syntax. Profile/precision/metadata/stride refusal precedes the only pixel allocation and reports an unsupported/layout/limit category as applicable.

Aggregate admission covers both compressed endpoints, one final padded pixel capacity and both workspace bounds. Pinned `ScalarCodec.swift` reserves a fixed 65536-byte context, a gradient table bounded by `2*(2*65535+1)*MemoryLayout<Int>.stride`, two compressed reader/writer buffers and, for the qualified single scan, exactly two `Range<Int>` directory capacities. The RLE direct kernels use no row/full-plane workspace; 16 UInt32 header words are reserved separately. Ancillary/mapping/restart profiles are excluded, so no unaccounted metadata or variable scan directory enters this bound. Both codecs receive explicit limits constrained to the aggregate remainder. Each codec counts its active compressed endpoint itself: encode limits subtract only the retained external input, and decode limits subtract only the reserved future output. Tests admit the exact boundary and deny one byte below it for both the small7x3 fixture and a nontrivial513x512 full16 case in both directions.

Ordinary unmodified-peer tests observe actual owner writes/encoder reads, matching allocation UUID, one SwiftRLE pixel allocation/release and zero copy bytes. The peer uses supplied destinations directly (`ScalarCodec.decode`, `ImageDestination.write`, `ScalarSampleWriter`), while encode borrows the sealed source (`ScalarSampleReader`); its only allocating-image branch is the absent-destination branch. A second separate instrumentation-only peer snapshot hooks the actual `OwnedImageStorage` constructor: a positive control observes one allocation; both real transcodes observe zero peer pixel allocations. The retained instrumentation patch/hash distinguishes this evidence from unmodified pinned-source qualification. Compressed writer materialization is an endpoint allocation, not a pixel copy. Sanitizer figures are not used as allocator evidence.

Host integration tests cover both directions/precisions, odd 7x3 fixtures, source padding invariance, different destination row strides and endian orders, independent JPEG-LS input, independent destination decode, concurrent actual encoder readers, foreign/stale leases, refused preflight reuse, zero-allocation refusal, after-write cancellation/invalidation, required-backend failure/preferred fallback, limits and owner release. Load-bearing mutations produce 13 stride and 12 endian sample mismatches and restore the correct path. Independent DCMTK `dcmcjpls +pc +el` preserves declared12-bit codestream precision; default raw DCMTK encoding uses allocated16 bits. DCMTK `dcmdjpls`/`dcmdrle` verify three routes at both precisions. Fixtures are synthetic CC0, with hashes/commands/tool versions in receipts.

## Consolidated operation reports

Each successful transcode returns both native `SwiftRLE.OperationReport` and `SwiftJLS.OperationReport` values, plus ordered decode/encode stage facts. Backend/fallback, fidelity, copy/conversion events (including reason, byte count and layouts), elapsed time, normalization and optional allocation/workspace figures retain their actual origin. JPEG-LS does not expose a normalization field, so its mapped field is unknown rather than an invented empty report. The aggregate fidelity is exact only when both native stages report exact samples; other native histories remain visible without an invented aggregate fidelity.

The aggregate counts the single shared owner and its actual padded capacity once. Codec allocation counts remain separate; unknown counts remain unknown. RLE's native pixel peak already includes the supplied owner even when its allocation count is zero, so native peaks are never added blindly to the shared capacity. If both stages report zero codec allocations, aggregate pixel capacity equals the one owner; otherwise aggregate peak capacity is unknown because overlap is unspecified. Native stage peaks remain available unchanged.

Named admitted RLE/JPEG-LS workspace bounds are conservative admission reservations, not measured peaks. The sequential measured workspace peak is the maximum of native peaks only when both are known; the current peer's unknown peak keeps the aggregate unknown. Regression fixtures independently exercise noncanonical12-in-16 RLE high bits: normalization remains reported through RLE decode/JPEG-LS encode, canonical reverse transcoding preserves samples, and owner/capacity accounting remains exactly once in both directions. A separate report-mapping unit test uses explicitly synthetic report facts to verify nonempty fallback, conversion, fidelity and unknown-measurement preservation; it is not codec qualification.

## External DICOMKit candidate and directional matrix

`DICOMKitCandidate` lives only in the separate integration package. It models application-owned rows/columns/allocated/stored bits/signedness/photometric/planar metadata and caller-owned destination storage, then calls canonical SwiftRLE. Tests cover monochrome1/2 unsigned/signed8/16,12-in-16, RGB/YBR_FULL planar/interleaved and palette indices without display transforms. Required photometric interpretation stays in the durable external frame contract. This is not a DICOMKit cutover or a DICOM parser; DICOMKit and all sibling checkouts remain untouched.
