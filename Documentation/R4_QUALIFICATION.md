# R4 measured optimization and security qualification

R4 is independently accepted and merged through PR #4 at `d43bc2aaec0c511c6e583dea42dcb57298d8a000` (accepted head `ae654f73f6fc6690b9472436577cac18ecdd4e85`; exact-head CI run `40093317140`, all seven jobs). This document describes methodology and scope; raw receipts bind actual results to source, binary, fixture, environment and command identities. It is not a stable release or device qualification claim.

## Implemented candidate and reference

Automatic execution hoists validated component/plane addressing out of the pixel loop. Explicit scalar execution preserves the reference lookup. Singleton images also use that lookup: batched measurements confirmed a setup regression in the first candidate, so final selection avoids constructing a hoisted address map for singletons and explicit reference policy. Both report scalar CPU, retain bounds, packet-work, cancellation and descriptor validation, and use the same direct final-output owner. The scalar predecessor is DICOMKit commit `4b68d7e22829418c88e48dd53d98b25fee50d90d`; the accepted successor baseline is SwiftRLE commit `a72aa30f84129c2add8b84008675061203f8bbc0`. The predecessor source is copied only into the development harness with its MIT provenance and minimal benchmark context; no protected predecessor or sibling checkout is built.

## Reproducible performance method

`Scripts/benchmark-r4.py` builds isolated ordinary release modules in a supplied output directory. It preserves separate timestamped runs while reusing the output directory's existing harness/build. Supply `--predecessor-source` pointing to the pinned `Sources/DICOMCore/RLECodec.swift`, whose expected hash is checked. `--quick --memory` is the smoke mode; `--memory` selects the complete run and fresh-process memory captures. Use `Scripts/summarize-r4.py RAW OUTPUT --memory MEMORY` to summarize raw samples. Run on a quiet controlled host with no sanitizer, tracing or coverage; shared-runner timings are advisory.

The selected manifest contains 56 cases and 112 operation rows. It covers 1×1, odd 17×13, 512×512, 2048×2048 and 3072×3072; flat/ramp/noisy; mono 8/12/16 meaningful bits, RGB 8/16 storage planar/interleaved, and YBR_FULL; packed and padded/offset storage, LE and BE where supported. Large dimensions deliberately select representative patterns instead of a costly Cartesian product. Synthetic values use a fixed integer coordinate/component expression recorded in the harness; fixtures are generated without external data and may be redistributed under CC0. Raw rows retain input logical digest, encoded digest, decoded storage digest, full descriptor fields, sizes and sample arrays. Every candidate sample is checked against independent coordinate-derived values, and candidate/scalar encoded bytes and decoded storage must agree. The measured harness initially screened predecessor output with its own roundtrip only. A subsequent separate untimed validation cross-decodes all 36 predecessor-supported outputs with the final SwiftRLE decoder and compares every logical value to the coordinate expression; padded and BE cases are explicit API exclusions. Migration output byte equality is not presumed.

Each operation has five warmups and twenty timed calls. All six predecessor/scalar/candidate orders rotate. Typed result owners survive until after the stop timestamp, and hashing, dictionaries, telemetry inspection and sample traversal occur outside the timer. Throughput uses logical bytes including components; padding contributes to storage/admission, not logical throughput. Encode size, ratio, noisy expansion, per-case median/p95/full spread and every threshold trigger remain visible.

Memory captures run in a fresh process per case/implementation/operation. Absolute process peak RSS includes executable/runtime, fixture/input preparation and codec execution. Setup peak is reported separately and is never subtracted from a cumulative maximum. Ordinary-build pixel allocation/release and copy counters observe the actual `OwnedImageStorage` constructor/release and conversion hooks. Compressed `Data` is separate from pixel/workspace counts; zero semantic workspace does not claim zero general heap activity. Process malloc-zone live blocks/bytes are snapshots, not cumulative allocation counts. A host-returned zero malloc maximum is unavailable high-water telemetry, not evidence of a zero peak. The final full benchmark and scratch experiments use an identical qualification-only high-water bookkeeping patch in BOTH scalar and candidate module copies, preserved per module as a patch. The recorder is inactive during timing and active only in the separate accounting/experiment scopes. These are not exact unmodified Telemetry copies; shipped production source is unchanged by this instrumentation. Sanitizer allocator/RSS figures are never substituted for ordinary accounting.

The reusable driver requires exact row identity sets/counts and zero exits. Historical measurements executed with older driver revisions require an additional explicit completeness audit; later script hashes are not retroactively attributed to those measurements.

## Unshipped experiments

`Qualification/Benchmark/experiments.swift` measures a portable SIMD16 bounded repeat scan against its scalar equivalent, including short lengths, packet tails, every split position and unaligned starts. This is a development experiment, not an accelerated backend. Four-frame serial versus bounded two-worker scheduling uses one immutable shared input, operation-specific aggregate buffer admission, at most two in-flight operations and deterministic output checks. Encode admission includes each worker’s conservative worst-case compressed output; decode admission includes each final image; the one retained shared source and compressed reference are counted separately. Recorder peaks cover in-scope decoder-owned output pixels, excluding that retained source. An untimed four-frame full-storage equality check covers every sample and padding byte at both sizes. A deterministic callback barrier cancels two active decodes after reconstruction/sealing but before successful return, joins them and checks release counts; it does not claim mid-packet cancellation from that particular experiment. Raw timing runs and isolated memory runs remain distinct. Frame scheduling timing includes its byte-equality/sample-sentinel checks symmetrically. Untimed validation helper copies are separate from codec handoff accounting. System runtime/stack and allocator overhead remain visible in process RSS rather than being described as codec buffer admission. No segment-lane parallel writes are introduced.

No Metal/GPU backend is shipped. Its dispatch/compilation/transfer experiment remains unexecuted; no GPU performance conclusion or automatic threshold is claimed. Variable-length packet state, CPU addressing gains and optional SIMD/frame experiments are the current measured work. CPU storage does not establish IOSurface/Metal/UMA compatibility.

Final repaired-source identity binds the 41-test core debug/release, CLI, consumer, oracle and sanitizer evidence. ## Limits

Per-case confirmed latency/RSS increases above 5% and unchanged-setting encoded-size increases above 1% require investigation. Raw triggers and targeted repeat evidence are retained for independent acceptance; this document grants no waiver. SIMD and frame concurrency remain unshipped until their separate correctness/security/platform costs justify adoption. R5 was subsequently independently accepted and merged at `942dfb9`, including native Mac/toolchain CI in final five-job run `40273685051` and available iPhone/iPad iOS 26 simulator evidence. Exact macOS 26.0 and physical iPhone/iPad tests remain UNEXECUTED and owner-waived as R5 gates under DEC-11; other-platform evidence is supplemental. DEC-12 separately authorizes the 1.0.0 source release. DICOMKit production cutover remains deferred during its separate review.

## Final repaired-source measurements

The measured `DICOMRLEFrame.swift` SHA-256 is `af27a0a54a982ce60f36137788180c4f0e4a0d18c522a4f1435c1ab125228160`. The host was Apple M4, macOS 27.0.1 build 26A434, Apple Swift 6.4 (`swiftlang-6.4.0.34.1`, clang `2100.3.34.1`) and SDK 27.0, with deployment remaining 26.0. The host drew AC power and reported no recorded thermal/performance warning. This is host engineering evidence; it does not execute the exact minimum OS or unavailable devices.

All 56 selected cases completed 112 timing rows and 296 distinct fresh-process memory captures. Every operation retained five warmups and twenty samples. The complete candidate/scalar median latency ratio range was 0.234–1.018; for non-singleton cases it was 0.234–0.695. There were no >5% per-case latency/RSS triggers or >1% encoded-size triggers on this final run. Candidate and accepted-scalar encoded bytes and decoded samples agreed for every case. Ordinary allocating decode observed one balanced final pixel allocation/release and zero pixel conversion copy bytes; encode observed no new pixel allocation. Per-case raw results, p95 and full spreads remain the evidence; these ranges are not a universal speedup claim.

The first address-hoisting candidate had reproducible singleton regressions. Investigation used 1,000 retained calls per sample, five warmup batches, twenty alternating timed batches and three fresh processes per case. The correction selects the reference path before constructing a hoist map for singletons and explicit scalar policy. Repaired pooled singleton candidate/scalar ratios ranged 0.988–1.029, with no case above 5% in all three repeats, followed by the full no-trigger run above. No regression threshold was waived.

The unshipped SIMD16 repeat-scan experiment passed 2,247 differential checks. At 128-byte flat runs its median ratio to scalar was 0.269, but early-break inputs cost 1.516× at 128 bytes and 1.567× at 64 bytes. The unconditional candidate is rejected; this microbenchmark does not justify changing the shipped PackBits engine.

The unshipped four-frame two-worker scheduler measured median elapsed-time ratios to one worker of 0.574/0.516 for encode/decode at 512² and 0.512/0.508 at 2048². It remains an explicit caller scheduling experiment, without an automatic backend or universal threshold. At 2048² the in-scope decoder-owned output peak was 8,417,280 bytes with one worker and 16,834,560 with two. Add the separately retained 8,417,280-byte shared source to obtain the owned-pixel total; the 4,788,016-byte compressed reference is separate. Fresh-process RSS was 28,377,088 versus 36,831,232 bytes. Codec buffer admission is not a whole-process RSS cap. Every result in an untimed four-frame batch matched all source storage bytes, including padding, at both sizes. Both active decoders reached the completed callback before cancellation, returned no successful result, joined and released both owners.

Final repaired-source ordinary core runs executed 41 tests in debug and release; AddressSanitizer and ThreadSanitizer separately executed 41 core and 14 shared-owner tests against the unmodified peer snapshot each, with zero skipped events. The separate ordinary peer allocator build executed 15 tests, including its extra instrumentation control: one positive-control peer allocation and zero additional handoff allocations. DCMTK verified the real directions and core profile matrix; libtiff verified PackBits interoperability. The final repaired-source supervisor passed with both jobs exiting zero: DICOM completed 3,600.000735292 seconds and 150,484,396 iterations; NRRD completed 3,600.03808225 seconds and 36,896 iterations. Both sampled runner descriptor counts remained 4 (latest and observed peak), failure logs were empty, and frozen inputs matched. The unchanged PackBits campaign is retained through explicit source/dependency review: 3,600.001264458 seconds and 210,255,007 iterations. Independent review of the final receipts passed for R4 acceptance. These results do not qualify unavailable devices or grant a stable release.

## Separate predecessor fidelity proof

The original predecessor timing run did not itself perform independent predecessor decoding. Its archived `main.swift` and executable remain byte-for-byte preserved. A later untimed `--validate-predecessor` run validated all 36 supported cases through the final SwiftRLE decoder and every coordinate-derived logical value. Every original fixture digest and predecessor encoded byte count matched, and every newly generated predecessor codestream also matched the preserved candidate codestream hash/bytes. This proof binds the exact pinned predecessor source, preserved fixture configuration and final successor source; it is not retroactively attributed to the old timing execution.

The reusable benchmark now performs that cross-decoder/value check in its untimed validation section, before warmups/timers, and offers the validation-only mode. Removing only those validation insertions reconstructs the measured `main.swift` exactly: timing bodies, fixtures and configuration are unchanged. The separate proof does not require timing remeasurement. Raw proof rows and the source-only delta are retained with engineering validation evidence.
