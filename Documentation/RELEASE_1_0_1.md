## Changes packaged relative to `v1.0.0` (`640e469fc9f6f9b9da59962b7f3b5a122f96373b`)

- **PackBits terminal-callback enforcement ([PR #7](https://github.com/raster-labs/SwiftRLE/pull/7), `244517fec6164cb60e075429cae96af661f88ff2`)**: `PackBitsEncoder.encode`, `PackBitsDecoder.IncrementalSession.finish` and `PackBitsDecoder.decodeIncremental` enforce task cancellation (`CancellationError`) and operation deadlines (`CodecError` `.resourceLimitExceeded`) after the terminal `.completed` progress callback, keeping failed incremental sessions permanently closed without publishing retained output.
- **CLI backend routing, deadline classification and test structure ([PR #7](https://github.com/raster-labs/SwiftRLE/pull/7), `244517fec6164cb60e075429cae96af661f88ff2`)**: Omitted and explicit `swiftrle-cli --backend automatic` route to `ExecutionPolicy.automatic` (preserving `scalar`/`scalar-cpu` reference selection, `preferred-accelerated` fallback and `required-accelerated` exit `4`). CLI remaining-deadline conversion samples the monotonic clock once at initial and refreshed `ResourceLimits` construction, preserving cancellation priority (exit `130`) and classifying nonpositive remaining time as deadline exceeded (exit `5`). Production CLI routing lives in internal `SwiftRLECLICore` behind thin executable target `SwiftRLECLI` (`swiftrle-cli`) so `SwiftRLECLITests` exercises `Main.run` in debug and release (`49` repository tests: `44` library + `5` CLI); `Scripts/validate-r1.py` validates combined and split test summaries, and [R4_QUALIFICATION.md](R4_QUALIFICATION.md) records the additive R4 receipt-link reconciliation.
- **Post-remediation `iOS 26.0` simulator and packaging rerun ([PR #8](https://github.com/raster-labs/SwiftRLE/pull/8), `75814f3743792cd41d2c02e483110aa44f2f7e51`)**: Records the 30 October 2026 bounded `iOS 26.0` simulator execution (`42/42` profiles each on representative iPhone and iPad, `0` failures, `0` skips) and fresh Swift 6.4 release CLI / HTTPS revision consumer / staged install-update checks on `244517fec6164cb60e075429cae96af661f88ff2` ([R5_QUALIFICATION.md](R5_QUALIFICATION.md)). Audited PR #8 head CI run `41008378477` (`76bfc07b28275cda2ff40e3535d84a770c883da3`, identical tree) and automatic post-merge `main` CI run `41010317176` (`75814f3743792cd41d2c02e483110aa44f2f7e51`) both passed all five jobs; these are existing `main` verification facts, not `1.0.1` release-branch CI.
- **`1.0.1` metadata and oracle wording clarification**: Advances `VERSION`, `swiftrle-cli` version/help literals and `ManPages/swiftrle-cli.1` metadata/date (`30 October 2026`) to `1.0.1`, and clarifies historical R2 `DCMTK`/`GDCM` wording in [IMPLEMENTATION.md](../IMPLEMENTATION.md). The accepted executed independent DICOM RLE oracle is `27` two-way `DCMTK` profiles (`libtiff` covers PackBits); `GDCM` was historical planning/handoff context with no `GDCM` execution or pass claim. Codec algorithms, public API, `Package.swift`, Apple OS `26.0` platform floors, Swift tools `6.2` minimum (`6.4` primary), zero external dependencies, all seven pinned common contracts ([COMMON_CONTRACT_SHA256.txt](COMMON_CONTRACT_SHA256.txt)), tests/drivers/CI and Apache-2.0/MIT notices remain unchanged from `75814f3743792cd41d2c02e483110aa44f2f7e51`.
