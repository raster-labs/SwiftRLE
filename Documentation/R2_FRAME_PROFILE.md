# R2 strict DICOM frame profile

Implemented locally for independent audit, based on accepted R1 main `60af084d25522fafebb71abfeb37f4635dc2af3b`. Publication, exact-head CI and independent acceptance remain separate gates.

The normative format reference is DICOM PS3.5 2026d: [8.2.2](https://dicom.nema.org/medical/dicom/2026d/output/chtml/part05/sect_8.2.2.html), [Annex G](https://dicom.nema.org/medical/dicom/2026d/output/chtml/part05/chapter_G.html), especially G.2 byte lanes, G.3 segments and G.5 header. The frame API does not parse DICOM datasets, fragment headers or patient metadata.

## Supported sample semantics

- Signed/unsigned 8/16-bit monochrome uses `[.grey]`, `.greyscale`.
- Unsigned palette indices use `[.uninterpreted("palette-index")]`, `.unknown`; no LUT expansion.
- Unsigned RGB uses `[.red, .green, .blue]`, `.rgb`.
- Unsigned YBR_FULL uses `[.uninterpreted("Y"), .uninterpreted("Cb"), .uninterpreted("Cr")]`, `.unknown`; no colour conversion.
- Meaningful precision is explicit, including 12-in-16. Encoding rejects noncanonical Image cells. Canonical decode masks/sign-extends while writing the last byte lane of each sample, and reports actual changes through `OperationReport.sampleNormalizations`. Logical samples retain exact values.
- All supported profiles admit explicit endian storage, offsets, padded rows, component strides, and interleaved/planar colour. Component mapping follows explicit plane descriptors; plane origins are never inferred.
- Binary packed, float, 32-bit, alpha, signed colour, subsampled and unspecified component profiles are rejected.

An external `RLEFrameDescriptor` is mandatory for Image inspection and decode. Per-call and configured descriptors resolve consistently; conflicting descriptors fail. Destination RAM layout may differ while sample/colour/ICC semantics agree. Metadata is carried by the descriptor's `metadata`, including external MONOCHROME1/MONOCHROME2 annotations and palette information where required by the caller. Neither `preserve` nor `discardAncillary` silently loses metadata: encoding metadata or ICC requires a configured external descriptor retaining it. The current scalar implementation conservatively retains supplied ancillary metadata even when discard is permitted. The caller keeps this descriptor alongside frame bytes; the compressed frame itself has no metadata container.

`DICOMRLEFrame.decodeAllocatedCells(_:descriptor:options:)` is an explicitly synchronous extension returning `RawAllocatedCells`, with a read owner and the original external descriptor. It preserves every allocated cell bit and never constructs a canonical meaningful-bit Image. It rejects conflicting profiles/descriptors, shares the same final scatter kernel, checks cancellation/deadline, and emits serial inspecting/completed progress outside borrows/locks. The Image-level async methods use `@concurrent`; synchronous wrappers execute on the calling executor.

## Strictness and resource accounting

The 64-byte header uses checked little-endian UInt32 conversion independently of RAM order. Segment count must match sample bytes times components, lie in 1...15, and have first offset 64, increasing bounded ranges, zero unused offsets and even segment lengths. Packets must produce exactly each row and frame; no clipping or missing-pixel repair occurs. Signed controls widen to Int before arithmetic. Following complete output, each segment admits at most 64 NOP controls, still charged to the checked `64 + pixels * maximumPacketOperationsPerOutputByte` budget, followed by exactly one zero pad only when needed for odd packet byte length. Every other trailing byte is rejected. Inspection checks structural header facts and external semantics, without full packet decoding; it is not a conformance certificate.

Decode has zero heap pixel workspace: packets scatter directly into final lanes, with bounded scalar packet state and at most 15 header ranges. Normalization is fused into the final lane write. Allocating and caller decode use the same kernel. Only `OwnedImageStorage` allocates pixels, instrumented at the actual allocation/release boundaries. The parser's bounded header bookkeeping is distinct from pixel workspace. Caller padding remains untouched; allocated storage initializes its complete capacity to zero. No full decoded planes, source repack, intermediate image file or external process is used by the library.

For encoding, each row's conservative bound is `width + ceil(width/3)` bytes under the R1 deterministic two-byte-repeat packet rule. The frame bound is `64 + segmentCount * (height * rowBound + 1)` including conservative per-segment padding. One compressed Data reservation/backpatch buffer holds header and segments; there is no compressed-segment staging array. Admission conservatively rejects operations whose bound exceeds compressed/aggregate limits, even when actual compression might fit. Source capacity, compressed output, metadata and ICC are admitted together. Decode admits compressed input, destination capacity including padding and metadata/ICC together. Dimensions, pixels, capacities and arithmetic are separately validated. One serial worker and zero pixel workspace satisfy positive worker/workspace ceilings; no parallel tasks are created by the kernel. Cancellation/deadline checks occur at bounded packets (maximum 128 samples), before allocations and before sealing/publication, including after external provider borrows return.

Metadata admission checks cancellation/deadline every 64 entries/required keys and every 1024 UTF-8 key bytes, without constructing an additional set of every entry key. Descriptor metadata comparisons also carry the operation gate. Inspection rechecks before returning, and allocating decode rechecks immediately before pixel allocation. Preflight header/layout/limit/metadata failures leave caller destinations reusable. A begun fill failure/cancellation aborts after borrows finish and prevents image publication. Destination metadata admission additionally respects its own retained limits before beginning writes, even if operation limits are looser.

## Reproducible host evidence

Run `python3 Scripts/validate-r1.py --build-system swiftbuild --output <evidence-directory>` using Swift 6.4; Swift 6.2 CI uses `--build-system native`. The historical script name is retained as the R1/R2 gate entry point. Required developer tools are libtiff `tiffcp`, DCMTK `dcmcrle`, `dcmdrle`, `dcmdump`, Python and pydicom 2.4.4. Missing tools fail. Core package resolution remains dependency-free. CI installs oracle tools explicitly and retains their version and synthetic fixture hashes in source-bound receipts.

The suite combines independent literal/header/sample fixtures, every-prefix truncation, malformed offsets/counts/padding, row-crossing/NOP checks, signed extrema and noncanonical 12-in-16 cells, profile/layout/endian matrices, allocation/copy telemetry, caller padding sentinels, metadata/ICC admission, concurrent reader encodes, owning lifetime and begun-write cancellation. Task-local mutations change the actual stride/endian paths; codestream differences are counted and the original task-local setting is automatically restored.

The DCMTK oracle covers 27 synthetic profiles in both directions. Pydicom independently constructs and extracts DICOM containers; DCMTK `dcmdump` validates required image tags. Extracted reference frames are reembedded and decoded before Swift tests consume them, comparing every native cell. Swift-produced frames are embedded/read back and decoded by real `dcmdrle`, comparing samples, precision, signedness and photometric interpretation. The deterministic fixture generator is `Scripts/dicom-oracle.py`; fixtures are synthetic CC0 and receipts include SHA-256 hashes and exact external commands.
